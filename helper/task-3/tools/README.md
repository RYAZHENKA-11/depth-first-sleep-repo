# Отладка: запуск и анализ

Локальный стенд повторяет судейский: ROS 2 **Humble** + Nav2 + slam_toolbox, только
собранный RoboStack под macOS/arm64 вместо Ubuntu. Значит локально гоняется та же ветка
кода, что поедет на зачёт, а не только реактивный fallback.

## 1. Разовая установка

```bash
tools/setup_ros.sh      # micromamba + ros-humble-desktop + Nav2 + slam_toolbox + MNN (~2 ГБ)
```

Проверить, что всё встало:

```bash
source tools/ros_env.sh
ros2 --help >/dev/null && python3 -c "import rclpy, numpy, MNN" && echo ok
```

## 2. Запуск

```bash
tools/debug.sh                 # Webots (GUI) + RViz2 — основной режим
tools/debug.sh --no-rviz       # только Webots
tools/debug.sh --headless 120  # без окон, 120 с, только логи — для быстрых прогонов
tools/debug.sh --quiet         # без телеметрии контроллера в консоли
```

`Ctrl+C` гасит всё разом, включая Nav2 и slam_toolbox, которые поднимает сам контроллер.

Без ROS вообще (быстрая проверка только реактивного контроллера): `./run.sh`.

## 3. Что смотреть в RViz

Fixed Frame — `map`. Вид сверху, привязан к `base_link`, то есть камера едет за роботом.

| Дисплей | Топик | О чём говорит |
|---|---|---|
| LaserScan | `/scan` | что робот считает препятствием ПОСЛЕ фильтрации пола и собственного корпуса |
| SLAM map | `/map` | карта, которую строит slam_toolbox |
| Local costmap | `/local_costmap/costmap` | по чему рулит контроллер; здесь видно, не закрашен ли проход |
| Global costmap | `/global_costmap/costmap` | по чему строится маршрут целиком |
| Global plan | `/plan` | маршрут планировщика (зелёный) |
| Local plan | `/local_plan` | траектория Pure Pursuit (синий) |
| Current goal | `/go2/goal` | куда `goal_manager` поставил цель (розовая стрелка) |
| Debug markers | `/go2/debug_markers` | стрелка на маркер, если камера его нашла |
| Front camera | `/go2/camera` | кадр, по которому работает перцепция |
| SLAM map (holst) | `/map_full` | та же карта на фиксированном холсте; выключен по умолчанию |

**Как читать глазами.** Робот едет туда, куда ведёт зелёный `Global plan`, и настолько
точно, насколько синий `Local plan` за ним следует. Если план отсутствует — планировщик
не смог построить маршрут (смотри costmap: скорее всего робот «в кольце»). Если план
есть, а робот стоит — смотри `Local costmap`: контроллер видит столкновение.

**Три вещи, которые ловятся только связкой дисплеев:**
- `LaserScan` против реальной сцены в Webots — если точки есть там, где пусто, сломана
  фильтрация (пол, собственный корпус, компенсация крена);
- `Front camera` против `Debug markers` — видит ли перцепция маркер и туда ли навелась;
- `Current goal` против `Global plan` — совпадает ли цель с тем, куда реально ведёт Nav2.

## 4. Что смотреть в консоли

При `GO2_DEBUG=1` (включено по умолчанию) контроллер печатает:

```
[participant]  Nav2 готов (1.4s) — переход на ROS2/Nav2
[goal_manager] t=29.1 pose=(5.02,0.11,0.35) stage=0 found=False nav=active
[goal_manager] t=29.1 цель[explore] stage=0 rel=+0.05 dist=8.00 -> (13.0,0.6)
[fallback]     t=0.7 mode=GAP front_min=0.625 target_bearing=0.254 vx=0.200 vyaw=0.355
[key_task]     t=9.0 ключ найден на точке сканирования xy=(0.08,0.31) area=0.3600
[referee]      cp1 scored (+10) @ 29.1s
```

- `stage` — какой маркер ищем: 0-2 это cp1-cp3 (жёлтый), 3 — финиш (фиолетовый);
- `found` — видит ли камера маркер прямо сейчас;
- `nav` — состояние цели Nav2: `active` / `succeeded` / `failed`;
- `цель[marker]` — ведём на маркер, `цель[explore]` — далёкая цель по курсу трассы;
- `mode=GAP/DEAD_END/BACKUP` — режим реактивного контроллера (только когда рулит он).

## 5. Логи

```
logs/run.log            весь вывод Webots и контроллера за прогон
logs/rviz.log           вывод RViz
controllers/participant/logs/nav2.log            узлы Nav2
controllers/participant/logs/slam_toolbox.log    slam_toolbox
```

Самое полезное в `nav2.log`:

```bash
grep -E "ERROR|WARN" controllers/participant/logs/nav2.log | grep -v "inflation radius"
```

Что означают типовые сообщения:

| Сообщение | Причина |
|---|---|
| `detected collision ahead!` | контроллер видит препятствие на пути — часто мусор в costmap |
| `Failed to make progress` | робот физически не двигается под активной целью |
| `No valid path found` | планировщик не построил маршрут: цель в занятой клетке или робот заблокирован |
| `Robot is out of bounds` | цель или робот вне холста costmap |

## 6. Диагностика из терминала

```bash
source tools/ros_env.sh

ros2 topic hz /scan               # идёт ли скан из моста (ожидаем ~30-60 Гц)
ros2 topic echo /cmd_vel --once   # что Nav2 велит роботу
ros2 node list                    # поднялись ли узлы Nav2 и slam_toolbox
ros2 run tf2_tools view_frames    # дерево TF: map -> odom -> base_link -> laser
```

## 7. Типовые ситуации

| Симптом | Куда смотреть |
|---|---|
| Робот стоит на старте | `nav2.log` на `collision ahead`; `Local costmap` в RViz |
| Едет не туда | `Current goal` и строки `цель[...]` — источник цели `marker` или `explore` |
| Дёргается на месте | частота строк `цель[...]`: цель не должна меняться чаще ~раза в 2 с |
| Проезжает мимо чекпоинта | `found=` в логе: если всегда `False`, перцепция не видит маркер |
| Nav2 не поднимается | `controllers/participant/logs/nav2.log` с начала файла |

## 8. Известные проблемы

- **Навигация застревает у старта.** Примерно в двух прогонах из трёх робот не уходит
  дальше 1-4 м: Nav2 не может построить путь и циклится на запасных дистанциях. Это
  главный ограничитель результата.
- **Финишный маркер не проверен.** Модель свечения выведена по жёлтому чекпоинту; для
  фиолетового финиша ожидаемый цвет (255,230,255) близок к белому, и проверка разброса
  каналов там не спасает. Нужен замер, когда робот доедет до финиша.

## 9. Осторожно: мир легко испортить

Webots при сохранении мира записывает в `level3.wbt` текущее состояние: позу робота,
углы суставов и **цвета маркеров**, которые судья перекрашивает по ходу заезда. Один
такой случай стоил долгой отладки: робот стартовал из середины трассы, а все три
чекпоинта были зелёными («уже взяты»), из-за чего перцепция не видела жёлтого вовсе.

`tools/debug.sh` запускает Webots с `--batch`, поэтому сохранения не происходит. Если
мир всё же испортился, эталон лежит рядом:

```bash
cp worlds/level3.wbt.orig worlds/level3.wbt
```

Признаки порчи: строки `hidden ...` в файле, робот не на старте, цвета чекпоинтов
отличаются от схемы (cp1 жёлтый, остальные синие, финиш фиолетовый).
